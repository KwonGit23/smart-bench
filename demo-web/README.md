# Smart Bench 로컬 시연

> 현재 저장소의 STM3에는 D 키 종료 요청 및 완료 응답 중계가 빠져 있습니다. 아래 6~7단계는 해당 중계가 연결된 구성의 사용 방법입니다. 현재 구현 범위와 연결 조건은 [프로젝트 README](../README.md#현재-소스-기준과-통합-상태)를 먼저 확인하세요.

1. 수정된 STM2, STM3, UNO 코드를 각 보드에 업로드합니다. STM1은 기존 코드 그대로 사용합니다.
2. **STM2의 ST-LINK USB 포트**를 데이터 전송이 가능한 USB 케이블로 노트북에 연결합니다. 기존 보드 간 배선은 그대로 사용합니다.
3. Python 3를 설치하고 `start.cmd`를 더블클릭합니다. 열린 주소를 **Chrome 또는 Edge**에서 사용합니다. 서버 창은 열어 두세요.
4. 웹 화면의 **STM2 연결**을 누르고 STM2의 `STMicroelectronics STLink Virtual COM Port`를 선택합니다. 같은 COM 포트를 사용 중인 시리얼 모니터는 닫아주세요. 포트 선택은 브라우저에서 직접 해야 합니다.
5. 무게 입력 → 최초 거치 보정 → 바를 들면 세트 시작 → 거치하면 세트 종료. 여러 세트를 반복합니다.
6. 전체 운동을 끝낼 때 바를 거치하고 **4×4 키패드 오른쪽 맨 아래 D**를 누릅니다. 노트북 키보드의 D가 아닙니다. 무게 입력 중이면 `*`로 입력을 지운 다음 D를 누르세요.
7. LCD에 `Finishing...` 이후 `Workout ended / See laptop / USB`가 표시되고, 웹에 세트별 결과가 나타납니다. 최종 데이터를 기다리는 시간은 최대 약 1.5초이며, 누락 시 해당 오류를 결과에 표시합니다. LCD의 완료 표시는 STM2 처리 완료를 뜻하며 노트북 수신 확인은 아닙니다.

바를 들고 있는 중에는 D로 운동을 종료하지 않습니다. 종료 이후 다시 바를 들면 새 운동의 첫 세트가 시작되며, 최초 보정값은 유지합니다. 웹은 다음 D 종료 결과가 도착할 때까지 이전 완료 운동을 표시합니다.

## 결과와 저장 범위

- STM2가 세트별 무게, 횟수, 평균/마지막 상승 시간, 최대 기울기, 보조 개입, 오류, 기존 불안정 점수와 추천 결과를 저장하고 계산합니다. 웹은 받은 값을 표시합니다.
- 반복이 없던 세트도 0회로 표시합니다. 3회 미만 또는 오류로 추천이 없는 세트의 점수는 ‘분석 보류’로 표시합니다.
- 기존 펌웨어의 `vl_pct`는 실제로 **상승 시간 증가율**이므로 웹에서도 이 이름으로 표시합니다.
- 운동당 **첫 32세트**를 보관합니다. 초과 세트 수는 경고로 표시하고 합계에 포함하지 않습니다. 매 반복별 원시 데이터 전체를 보관하는 기능은 아닙니다.
- 마지막 완료 운동은 STM2 RAM에 유지되며 약 3초 간격으로 재전송됩니다. D를 누른 뒤 웹을 연결해도 받을 수 있습니다. 전원을 끄면 보드 기록은 사라집니다. 웹의 **결과 저장**으로 JSON 파일을 저장할 수 있습니다.
- 결과 전송은 USART2 PA2/ST-LINK VCP, **115200 / 8N1**을 사용합니다. 웹은 읽기만 하며 모터나 세트를 제어하지 않습니다. 인터넷이나 별도 서버 계정은 필요 없습니다.
- 원래 진단 로그와 함께 `@BENCH ` 접두어의 JSON 행을 전송합니다. begin → set → end의 개수와 번호가 모두 일치한 결과만 화면에 반영합니다. 부분 수신 시 다음 재전송을 기다립니다.

## 코드 위치

- `../stm2/Core/Src/main.c`
- `../stm3/Core/Src/main.c`
- `../uno/uno.ino`
- `dist/`: 외부 라이브러리 없이 실행되는 HTML/CSS/JavaScript

STM 소스는 기존 CubeIDE 프로젝트로 빌드 후 업로드합니다. `main.c` 파일 자체가 업로드용 바이너리는 아닙니다.

브라우저 USB 시리얼 구현 참고: [Chrome Web Serial 공식 문서](https://developer.chrome.com/docs/capabilities/serial/).
